## 🧭 מה זה

עיצוב ובנייה מחדש, מהיסוד, של האתר של רשת מרפאות פיזיותרפיה. האתר הקודם היה צריך מראה אחיד, נראות טובה יותר בחיפוש ודרך אמינה להפוך מבקרים ללידים. הפתרון הוא **ערכת עיצוב עצמאית ל-WordPress** שמותקנת *לצד* האתר הקיים ומשתמשת באותם סוגי תוכן, שדות ACF, תפריטים וחיבורי טפסים. כך אפשר היה לצפות בה על הדומיין החי ולהפעיל אותה **בלי הגירת נתונים ובלי רגע של השבתה**. שכבה אחת של design tokens מזינה כל סקשן, העמודים מרונדרים בשרת לטובת SEO, וכל מסלול ליד (שאלון, טפסים, טופס צף) עובר בצינור אחד שמתחיל במייל ורק אחר כך מסנכרן ל-CRM.

### חיפוש, נתונים מובנים ונראות במנועי AI

הנראות בחיפוש בנויה בתוך ערכת העיצוב עצמה, ולא מגיעה מתוסף. היא מורחבת גם ל**מנועי התשובות של AI**.

| שכבה | מה נבנה |
| ----- | -------------- |
| **נתונים מובנים** | ‏**JSON-LD של schema.org** שנכתב ביד: `MedicalClinic` ו-`LocalBusiness` (שם, טלפון, כתובות הסניפים, אזורי שירות), ‏`Organization`, ‏`Physician`, ‏`WebSite` (עם `SearchAction`), ‏`BreadcrumbList`, ‏`MedicalWebPage`, ובנוסף **`FAQPage` שנוצר אוטומטית** וקורא את האקורדיון בעמוד בזמן הרינדור. כך כל שאלה נפוצה, היום *ובעתיד*, מזינה את התוצאות העשירות של Google בלי תחזוקה |
| **מטא ושפה** | **כותרות ותיאורים** לכל עמוד, ‏**canonical** שמפנה לעצמו, ‏**hreflang** (`he` ו-`x-default`), ‏**Open Graph** מלא ו-Twitter `summary_large_image`, והנחיות robots ‏`max-image-preview:large` ו-`max-snippet:-1` בכל עמוד |
| **GEO / AIO** (חיפוש AI) | קובץ **`llms.txt`** מובנה למודלי שפה (סיכום השירותים, נקודות הוכחה, כל עמוד מפתח לפי קטגוריה), ו**רשימת היתרים מפורשת לסורקי AI** ב-`robots.txt` (GPTBot, ‏ClaudeBot, ‏PerplexityBot, ‏Google-Extended, ‏Applebot-Extended, ‏CCBot …), כדי שהמרפאה תוכל להופיע ב-**ChatGPT / Gemini / Perplexity** ובסקירות ה-AI של Google |
| **אינדוקס וגילוי** | מפות אתר XML (אינדקס, עמודים ומטופלים), מאומתות ב-**Google Search Console** וגם ב-**Bing Webmaster Tools**. בדיקת SEO חיה לכל עמוד אישרה מטא-דאטה ייחודית וממוקדת במילות מפתח בכל האתר |
| **אימות מייל** | ההגנה המלאה מפני התחזות, מוגדרת ב-DNS: **SPF + DKIM + DMARC** |

## 🧱 ארכיטקטורה

![Architecture](docs/showcase/architecture.png)

**ערכת עיצוב קלאסית ל-WordPress שמרונדרת בשרת** (בלי בונה עמודים ובלי פריימוורק בצד הלקוח), שיושבת מעל הנתונים הקיימים של המרפאה: סוגי תוכן, שדות ACF ותפריטים. שכבת התצוגה בנויה מתבניות PHP, משכבת design tokens ב-CSS וממודולי JavaScript נפרדים. כל מסלול ליד (חלון השאלון, כל טופס Contact Form 7 והטופס הצף שמופיע בגלילה) מגיע ל**נקודת קצה אחת** ב-`admin-ajax`. שם רצה קודם הגנה מספאם (honeypot נסתר והגבלת קצב לכל IP), אחר כך **נשלח מייל למרפאה**, ורק אז הליד נדחף ל-CRM ברקע. פרטי הגישה יושבים בקבועים של `wp-config.php`, אף פעם לא בערכת העיצוב, ואפשר לדרוס אותם דרך filter אחד של WordPress.

## 🧠 החלטות הנדסיות

- **ערכת עיצוב עצמאית לצד האתר הקיים** ← משתמשת באותם סוגי תוכן, שדות ACF, תפריטים וחיבורי טפסים, ולכן אין הגירת נתונים ואין השבתה במעבר ← המחיר: הערכה החדשה חייבת להישאר תואמת למודל התוכן הקיים.
- **קודם לתפוס, אחר כך לסנכרן** ← המרפאה מקבלת כל ליד במייל לפני הקריאה ל-CRM, כך שתקלה ב-CRM לא מפילה ליד ← המחיר: הסנכרון ל-CRM נעשה ברקע ובמאמץ הטוב ביותר, והכישלונות שלו אף פעם לא מגיעים למבקר.
- **עוזר מקומי לפי מילות מפתח במקום API של AI** ← אין עלות להודעה ושום מידע של מבקר לא יוצא מהאתר ← המחיר: הוא עונה רק על מה שיש במאגר הידע, ולכן שאלות שלא נענו ומשוב 👍/👎 נשמרים כדי להרחיב אותו.
- **PHP מרונדר בשרת ו-JavaScript נקי, בלי בונה עמודים ובלי פריימוורק** ← HTML ידידותי ל-SEO, בלי עלות hydration, בלי שלב בנייה ובלי נעילה לספק ← המחיר: כל סוג עמוד הוא תבנית שנכתבה ביד.
- **בחירת תבנית לפי כתובת או שם העמוד** ← מרכז השאלות, תת-הנושאים וכל נושא עתידי מקבלים את פריסת המאמר בלי הגדרה ידנית ← המחיר: ההתאמה נשענת על מוסכמת שמות.
- **קבוע גרסה אחד לכל שחרור** ← העלאה שלו מרעננת גם את מטמון הנכסים, ונקודת קצה ישנה ומוקשחת לידים נשארת פעילה בזמן רענון המטמון ← המחיר: נקודת קצה נוספת נשמרת לזמן קצר אחרי כל עדכון.

משמעת מסירה: **בדיקת lint של PHP על כל תבנית** לפני האריזה, וחבילת מסירה ללקוח עם **מדריך התקנה** מאויר, **מפת דרכים לביצועים** ו**תוכנית פעולה ל-SEO / CRO**.
